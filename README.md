# Luma — Lucky Number

A React + Vite application with Supabase email/password authentication and a private lucky-number profile for each user. The lucky number and profile are generated by a database trigger after account creation; the browser never chooses or writes the number.

## Run locally

1. Install Node.js 20.19+ (or 22.12+) and run `npm install`.
2. Create a Supabase project at [supabase.com](https://supabase.com).
3. Copy `.env.example` to `.env.local` and fill in the project's **Project URL** and public **anon** or **publishable** key from Supabase Settings → API.
   - These values are intended for the frontend. Never put a service-role key in a `VITE_` variable or in browser code.
4. In Supabase, open **SQL Editor**, paste and run [`supabase/migrations/202611230001_create_profiles.sql`](./supabase/migrations/202611230001_create_profiles.sql).
5. In Authentication → URL Configuration, set the local site URL to `http://localhost:5173`. If email confirmations are enabled, ensure the redirect URL allows your local app.
6. Start the frontend with `npm run dev`, then open the URL Vite prints (usually `http://localhost:5173`).

Use `npm run build` to create a production build and `npm run preview` to serve it locally.

## Supabase behavior

- Register with a name, date of birth, email, and password. Supabase Auth manages passwords and sessions.
- The SQL trigger creates `public.profiles` using Auth user metadata and assigns a number from 1 to 99. The number remains fixed for the account. The dashboard can also create a missing profile for an existing account through an authenticated, user-scoped database function.
- The `profiles` table has Row Level Security enabled. Authenticated users can only select their own row; browser clients cannot insert, update, or delete profiles.
- If email confirmation is on, registration displays a confirmation message. Confirm the email and sign in to open the dashboard.
- The dashboard is protected by the current Supabase session. When credentials are missing, the public pages remain usable and forms explain how to configure Supabase; authentication is never simulated.

The app does not require Supabase Storage. Keep `.env.local` private; only the public project URL and anon/publishable key belong there.
